# SPEC-018: Web publications as the second corpus

Feature:      Web publication ingestion and concordance
Priority:     P0 — the only source that can still grow, and the only one with an opposition channel
Status:       See `SPEC-018.status`
Dependencies: SPEC-001 (schema, migrations), SPEC-011 (actor matching), SPEC-013 (stance), D-034
Related docs: D-033 (broadcast block), D-034 (two corpora), `docs/G8-VALIDATION.md`
Tier:         `[SW]` Structured

## 1. Overview

The broadcast corpus is frozen at 263 videos because YouTube blocks transcript access at the IP level (D-033).
The same channels publish text on their own sites, and those sites answer normally. D-034 makes that a second
corpus: **publications**, ingested from RSS where a feed exists and from listing pages where it does not.

The point is not to replace television. It is to have a corpus that can grow, contains an **opposition** channel,
and therefore can answer the question the broadcast corpus cannot: whether the stance model recognises criticism
of an incumbent.

### Non-goals

- **No merged numbers.** A publication is not a broadcast segment; shares from the two corpora are never added,
  averaged or compared as if they were the same unit (D-034 §1).
- No full-text redistribution: body text is transient, and only title, URL, date, excerpt and embedding persist.
- No comments, social media, video/audio files, or pages outside a source's listing.
- No programme *video* analysis: a programme page is stored as a publication about a programme.

Leaning labels are editorial judgements stored as data, following the pattern of the reference project
(`razmikb/georgian-news-analyses`): revisable, attributable, never generated by a model.

## 3. Acceptance criteria (EARS)

- **FR-1** WHEN a source has an RSS feed, THE SYSTEM SHALL ingest it; WHEN it has none, THE SYSTEM SHALL scrape
  its listing page and SHALL NOT paginate beyond the configured limit.
- **FR-2** THE SYSTEM SHALL store one row per publication keyed by URL, with source, title, publication time,
  programme label when the site provides one, a short excerpt and a body hash.
- **FR-3** THE SYSTEM SHALL fetch at most one request per second per source and SHALL honour `robots.txt`
  (disallowed paths are never requested).
- **FR-4** WHEN a source is configured headline-only, THE SYSTEM SHALL NOT request its article pages.
- **FR-5** THE SYSTEM SHALL record which corpus each row belongs to, and every downstream query SHALL filter by
  corpus explicitly.
- **FR-6** THE SYSTEM SHALL reuse the existing actor matcher and stance classifier on publication text, with the
  same prompt version and gates.
- **FR-7** THE SYSTEM SHALL run a **concordance study**: over a window where both corpora exist, compare the
  topic mix and actor mentions of one channel's publications against its broadcast segments, and report the
  measured agreement with its method.
- **FR-8** WHEN the concordance agreement is below the configured threshold, THE SYSTEM SHALL label the web
  figures as "what the site published" and SHALL NOT describe them as airtime.

## 4. Boundaries

✅ Always: state the corpus; keep leaning labels as data; respect robots and rate limits.

⚠️ Ask first: fetching Formula article bodies; adding a source; increasing scrape volume.

🚫 Never: merge corpora in one figure; store full article text in the repository; infer a leaning from a model.

## 5. Testing

Parsers are tested offline against saved fixtures (the pattern the reference project uses), so no test touches
the network. Robots handling, the headline-only mode, corpus filtering in queries, and the concordance
computation each get their own test.
